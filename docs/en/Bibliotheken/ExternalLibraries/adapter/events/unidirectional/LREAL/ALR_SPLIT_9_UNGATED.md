# ALR_SPLIT_9_UNGATED

> ℹ️ **UNGATED variant:** This block is the ungated version of [`ALR_SPLIT_9`](ALR_SPLIT_9.md). It suppresses **no** unchanged repeats – every newly computed result is forwarded unconditionally, even without a value change. This matters for consumers that need a periodic cadence regardless of value change (e.g. derivative/frequency calculations that would otherwise fail to decay toward zero). Any change-detection/gating statements further down this page do **not** apply to this block.

## Introduction

The **ALR_SPLIT_9_UNGATED** is a generic function block that splits an incoming ALR signal (unidirectional adapter) into exactly nine identical outputs. It functions as a 1:9 splitter for the adapter type `ALR` from the package `adapter::types::unidirectional`.

## Interface Structure

### **Event Inputs**

None.

### **Event Outputs**

None.

### **Data Inputs**

None.

### **Data Outputs**

None.

### **Adapter**

| Direction | Name | Type |
| ---------- | ------ | ----- |
| **Socket** | `IN` | `ALR` (unidirectional) – The input that is distributed to the nine outputs. |
| **Plug** | `OUT1` … `OUT9` | `ALR` (unidirectional) – The nine outputs to which the incoming signal is provided. |

## Functionality

The module forwards the ALR signal present at socket `IN` unchanged and without delay to all nine plugs (`OUT1` to `OUT9`). No processing, conversion, or state logic takes place – the function block (FB) implements pure signal distribution at the adapter level.

## Technical Features

- The FB is generic and has the attributes `GenericClassName` (value: `'GEN_ALR_SPLIT'`) and `TypeHash`.
- It uses only adapter interfaces; no events or input/output data are defined.
- Since no algorithm or state machine is implemented, the FB operates passively and efficiently.

## State Overview

The FB has no state machine because it has no internal logic or memory behavior.

## Application Scenarios

- **Signal Distribution:** An ALR event generated by a controller should reach multiple actuators or components simultaneously.
- **Redundant Control:** Several identical devices must receive the same output signal (e.g., parallel hydraulic valves in agricultural machinery).
- **Monitoring:** A signal should be passed to a monitoring unit and simultaneously to the actual device without interference.

## Comparison with Similar Function Blocks

- **ALR_SPLIT_4 / ALR_SPLIT_8:** Analog function blocks with a different number of outputs.
- **Data Type Splitters (e.g., `SPLIT_INT`):** These operate at the data level, while `ALR_SPLIT_9_UNGATED` operates at the adapter level (signal/event forwarding).
- **Adapter Multiplexers/Demultiplexers:** Unlike these, `ALR_SPLIT_9_UNGATED` does not select or combine signals, but simply forwards the incoming signal 1:9.

## Change Detection

This block performs **no** change detection. Every newly computed result is written to the output and its adapter event fired unconditionally, regardless of whether the value differs from the previous run.

## Conclusion

The **ALR_SPLIT_9_UNGATED** is a simple yet practical function block for distributing a unidirectional ALR signal across nine parallel paths. It is easy to understand, requires no resources for logic or states, and can be directly integrated into control programs that require signal duplication.
