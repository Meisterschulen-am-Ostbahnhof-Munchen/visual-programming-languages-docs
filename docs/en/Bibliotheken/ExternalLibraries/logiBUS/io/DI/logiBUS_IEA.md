## Introduction
The composite function block `logiBUS_IEA` is used for event-driven processing of digital input data in a logiBUS fieldbus system. It encapsulates an internal `logiBUS_IE` block and makes its functionality available via a standardized interface. The function block enables the initialization and querying of events at a digital input and forwards the resulting indications to the resource via an adapter.
## Interface Structure

### **Event Inputs**

| Name | Type | Comment | Data Carried |

|------|-----|------------|-------------------|

| `INIT` | EInit | Service Initialization | `QI`, `PARAMS`, `Input`, `InputEvent` |

| `REQ` | Event | Service Request | `QI` |

### **Event Outputs**

| Name | Type | Comment | Data Carried |

|------|-----|-----------|-------------------|

| `INITO` | EInit | Initialization Confirm | `QO`, `STATUS` |

### **Data Inputs**

| Name | Type | Comment | Initial Value |
|------|-----|-----------|-------------|

| `QI` | BOOL | Event Input Qualifier | – |

| `PARAMS` | STRING | Service Parameters | – |

| `Input` | `logiBUS::io::DI::logiBUS_DI_S` | Identifies the input (e.g., Input_I1..I8) | `logiBUS_DI::Invalid` |

| `InputEvent` | `logiBUS::io::DI::logiBUS_DI_Events_S` | Identifies the event (e.g., Down, Up, Single-Click, Double-Click) | `logiBUS_DI_Events::Invalid` |

### **Data Outputs**

| Name | Type | Comment |

|------|-----|-----------|

| `QO` | BOOL | Event Output Qualifier |

| `STATUS` | STRING | Service Status |

### **Adapters**

| Name | Type | Comment |

|------|-----|-----------|

| `IN` | `adapter::types::unidirectional::AE` | Indication from Resource |

The adapter `IN` receives the events generated by the internal function block (`DI.IND` and `DI.CNF`) and forwards them as an "Indication" to the higher-level resource.

## Functionality

The function block `logiBUS_IEA` operates as a pure composite function block, meaning it has no control over its own flow. Instead, it forwards all events and data to the embedded function block `logiBUS::io::DI::logiBUS_IE`.

- **INIT Event**:

The internal function block is initialized via the event input `INIT`. The parameters `QI`, `PARAMS`, `Input`, and `InputEvent` are passed. After successful initialization, the internal function block acknowledges with the event `INITO`, which is returned to the higher-level function block. The output data `QO` and `STATUS` are updated in the process.

- **REQ Event**:

With `REQ` (if `QI` is set), a request is sent to the internal function block. This block processes the configuration and triggers the corresponding actions when events are detected.

`` - **Indication via Adapter**:

The events `IND` (Indication) and `CNF` (Confirm) generated by the internal function block are routed to the adapter output `IN.E1`. This allows the surrounding resource to react to events such as button presses or double-clicks.

## Technical Features
- **Composite Function Block**: The function block does not contain its own ECC (Execution Control Chart) but delegates all logic to the internal `logiBUS_IE`. This increases reusability and testability.
- **Generic Parameterization**: System-specific parameters can be passed as strings via the `PARAMS` input.
- **Adapter-Based Event Output**: The use of a unidirectional adapter (type `AE`) enables flexible coupling to the resource without hardwiring to event outputs.
- **Typed Input Selection**: The inputs `Input` and `InputEvent` utilize specific enumeration types (`logiBUS_DI_S` and `logiBUS_DI_Events_S`) that allow for secure and unambiguous configuration.

## State Overview

Since `logiBUS_IEA` is a pure composite component, it does not have its own state machine. The state is determined by the internal component. Typical states of the internal `logiBUS_IE` include:

- **IDLE**: Waiting for INIT or configuration
- **WAIT**: Waiting for a detected event at the input
- **ACTIVE**: Event detected, indication sent
- **ERROR**: Initialization or communication error

The state transitions are indicated by the events `IND` and `CNF` and communicated externally via the adapter.

## Application Scenarios
- **Event Detection at Digital Inputs**: Pushbuttons, switches, or sensors with multi-click functionality (single/double click) can be configured via `InputEvent`.
- **Machine Mode Control**: A digital input triggers a mode change when activated (e.g., a down event).
- **Configurable Initialization**: Bus parameters or filter times can be passed to the logiBUS controller via `PARAMS`.
- **Integration into Larger Composite Blocks**: The adapter `IN` allows connection to a higher-level control block (e.g., a resource manager).

## Comparison with Similar Blocks

| FB Type | Property |

|--------|-------------|

| `logiBUS_DI` | Pure digital input without event detection; simple level retrieval |

| `logiBUS_IEA` | **This FB:** Event-based input with initialization and adapter for indication |

| `logiBUS_DI_Events` | Event Detection on a Single Input, but Without Initialization Logic |

Compared to a simple digital input, the `logiBUS_IEA` offers a complete initialization interface and standardized event signaling via an adapter. Compared to a pure event block, it also includes the INIT functionality required for commissioning a logiBUS device.

## Conclusion

The `logiBUS_IEA` composite block encapsulates the complex initialization and event processing of a logiBUS input module in a compact, reusable unit. Thanks to the clear separation of initialization and request processing, support for typed inputs, and adapter-based event output, it is particularly well-suited for use in modular automation solutions where reliable event-driven input acquisition is required.
