# BYPASS_AX_BOOL

![BYPASS_AX_BOOL](./BYPASS_AX_BOOL.svg)

* * * * * * * * * *
## Introduction

The function block `BYPASS_AX_BOOL` implements a bypass function for a Boolean signal. It passes the value of the input `IN` directly to the output `OUT` and simultaneously creates a bypass path connected via an adapter. This path allows an external signal (`BY_IN.D1`) to be inserted into the internal logic and outputs the result via the output adapter `BY_OUT`.
## Interface Structure

### **Event Inputs**

| Name | Type | Description |
|------|-----|---------------|
| REQ | Event | Normal Execution Trigger |

### **Event Outputs**

| Name | Type | Description |
|------|-----|--------------|
| CNF | Event | Execution Acknowledgement |

### **Data Inputs**

| Name | Type | Description |
|------|-----|--------------|
| IN | BOOL | Input Signal |

### **Data Outputs**

| Name | Type | Description |
|------|-----|--------------|
| OUT | BOOL | Pass-Through Input Signal (Identical to IN) |

### **Adapters**

| Role | Name | Type | Direction | Description |
|-------|------|-----|----------|--------------|
| Plug | BY_OUT | `adapter::types::unidirectional::AX` | Output | Outputs the stored bypass state |
| Socket | BY_IN | `adapter::types::unidirectional::AX` | Input | Receives the bypass input signal (D1) and event (E1) |

## Functionality

Upon each event `REQ`, the output `CNF` is immediately set (event pass-through). Simultaneously, the data word `IN` is copied directly to `OUT`.

Internally, an OR operation is performed between `IN` and the adapter signal `BY_IN.D1`. This operation is triggered by `REQ` or by the event `BY_IN.E1`. The result of the OR operation is stored in an edge-triggered D flip-flop; the clock edge is generated by the completion of the OR calculation (event `CNF` of the internal OR block). The stored value of the flip-flop is output via the output adapter `BY_OUT.D1`, and the corresponding event output `BY_OUT.E1` is activated.

The module thus functions as a combination of a simple passthrough for `IN → OUT` and an edge-triggered bypass path that links and stores the incoming adapter signal with the current `IN`.

## Technical Features

- The direct connection to `IN → OUT` is established without delay via internal logic – the value is available immediately.
- The bypass path uses a D flip-flop (`E_D_FF`) for state storage. The stored value is only updated on a rising edge of the internal clock, which is generated by the OR operation.
- The adapter `BY_IN` must be connected to use the bypass path; without it, the module behaves like a simple passthrough.
- The event `BY_IN.E1` can trigger the OR operation independently of `REQ`, allowing the bypass to be updated asynchronously.

## State Overview

The component does not have an explicit state machine, but the internal D flip-flop stores a Boolean state (`Q = 0` or `Q = 1`). This state represents the last valid bypass value, which is output via the output adapter. The state only changes on a rising edge of the clock signal (completion of an OR operation).

## Application Scenarios

- **Manual Override** of a digital signal in automation technology: The normal value (`IN`) is passed to the controller, while a manual intervention (e.g., via an operator interface) can be added and stored via the bypass.
- **Signal Monitoring and Correction**: An external monitoring system can display a correction value via the bypass adapter, which is then linked to the original signal.
- **Bypass for Testing Purposes**: During commissioning, the normal path (IN→OUT) can be maintained, while a test signal can be inserted via the bypass.

## Comparison with Similar Function Blocks

- **Simple Passthrough** (e.g., `MOVE`): Would only transfer `IN` to `OUT`, without the possibility of external intervention.
- **Set/Reset Flip-Flop** (e.g., `SR`): Allows setting and resetting an output, but without directly passing through the input.
- **Selection Block** (e.g., `SEL`): Selects between two inputs – in this case, the input is always passed through, and the bypass is additively configured.

The `BYPASS_AX_BOOL` combines pass-through with integrated, edge-triggered logic for external signals.

## Conclusion

The `BYPASS_AX_BOOL` function block is a specialized component for applications where a Boolean signal is passed through unchanged, but an external bypass signal is simultaneously mixed in and stored. The combination of direct passthrough and edge-triggered OR logic with memory enables flexible intervention in signal chains without interrupting normal operation. This component is particularly suitable for control systems that require both standard operation and temporary or permanent overrides.
