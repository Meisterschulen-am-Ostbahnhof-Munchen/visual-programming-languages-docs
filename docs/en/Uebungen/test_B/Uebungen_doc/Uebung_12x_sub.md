# Exercise_12x_sub: Subapplication Type

* * * * * * * * * *
## Introduction

The sub-application `Uebung_12x_sub` implements logic for handling ISOBUS transmission callbacks. It is used to generate data for a CAN message cyclically or event-driven, with the message content (payload) being dynamically modified by a counter.
## Function Blocks (FBs) Used

In this sub-application, various function blocks are combined to implement a counter loop that converts its values into a CAN message format.

### Sub-Blocks: Exercise_12x_sub

- **Type**: SubAppType
- **Internal Function Blocks Used**:
- **Callback FB**: `isobus::pgn::tx::CallbackFB`
- **Parameters**: `DI1` = `[16#FF, 16#FF, 16#FF, 16#FF, 16#FF, 16#FF, 16#FF, 16#FF]` (Data array initialization)
- **Adapter Connection**: `PLUG1` (Connection to the adapter interface)
- **E_CTU**: `iec61499::events::E_CTU`
- **Type**: Up Counter
- **Parameters**: `PV` = `UINT#0` (Process variable / Limit)
- **STRUCT_MUX**: `eclipse4diac::convert::STRUCT_MUX`
- **Type**: Structured multiplexer for creating the CAN message
- **Attributes**: `StructuredType` = `isobus::pgn::CAN_MSG`
- **Parameters**: `u16DaSize` = `0`
- **Parameters**: `u8Priority` = `7`
- **BYTES_TO_ARR08B**: `logiBUS::utils::conversion::arr::reversing::BYTES_TO_ARR08B`
- **Type**: Converter from individual bytes to a byte array (8 bytes)
- **Parameters**: `IN_01` to `IN_07` = `16#00` (Fills the remaining bytes with 0)
- **F_USINT_TO_BYTE**: `iec61131::conversion::F_UINT_TO_BYTE`
- **Type**: UINT to BYTE converter (instance name indicates USINT usage)
- **Functionality**:

This sub-module coordinates the data flow between an ISOBUS callback and the generation of new user data. A counter reading is converted into a byte, integrated into a byte array, packaged into a CAN message, and made available to the callback module.

## Program Flow and Connections

The flow within the sub-application forms a feedback loop that updates the data content with each callback request:

1. **Trigger**: The `CallbackFB` sends an event via the output `REQ`.
2. **Count Up**: This event triggers the `CU` (Count Up) input of the counter `E_CTU`, incrementing the counter value.
3. **Conversion**:
- The current counter value (`CV`) is passed to the `F_USINT_TO_BYTE` function block.
- After successful counting (`CUO`), the conversion is triggered.
4. **Array Creation**:
- The converted byte is passed to input `IN_00` of the `BYTES_TO_ARR08B` block. This is the first byte of the message.
- Inputs `IN_01` to `IN_07` are statically assigned to `0x00`.
5. **Message Creation**:
- The generated byte array (`OUT`) is passed to data input `data` of the `STRUCT_MUX`.
- The `STRUCT_MUX` creates a structure of type `isobus::pgn::CAN_MSG` from this.
6. **Feedback**:
- The completed structure (`OUT`) is fed back to input `DI1` of `CallbackFB`.
- The multiplexer's acknowledgment event (`CNF`) triggers `CNF` of `CallbackFB` to complete the data update.

This exercise demonstrates advanced data manipulation and event chains in 4diac, specifically how adapter callbacks can be used to send dynamically changing data (in this case, an incrementing value).

## Summary

Uebung_12x_sub` represents a sub-application that operates an ISOBUS callback mechanism. It uses an internal counter to increment the first byte of the 8-byte payload of a CAN message with each callback. This is ideal for testing cyclic transmissions and the correct handling of data changes in a distributed control system.
